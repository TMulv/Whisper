## Root Cause Hypothesis

There are **two independent real bugs** plus a **deployment gap**:

1. **Real bug — EPUB (HIGH):** The single-writer design's three triggers don't cover *"user reads briefly on one chapter then leaves the screen."* The previously-removed `beforeRemove` write is exactly the trigger that closes this gap. Removing it in Phase 03 R3 was a regression; the in-tree A2 patch is the right shape but bypasses `positionStore.savePosition`.

2. **Real bug — Audio (MEDIUM):** `NowPlayingContext` has no AppState-background listener, so force-quit during playback loses up to ~7 s of position. Cold-open also never refreshes the saved audio position until the user presses play.

3. **Deployment gap (HIGH):** Both A2 patches are uncommitted, so the user's installed binary is identical to what produced the 12:24 forensic. Even if the patches are correct, they aren't running.

The user's instinct — *"introduce a manual action to mark where I left off"* — is independently correct and worth implementing **regardless of fixing 1 and 2**, because:
- It's deterministic: a single explicit user gesture writes through `positionStore.savePosition` with `trigger: 'manual-mark'`. Bypasses every gate.
- It doubles as the audio↔EPUB handoff point the user described ("highlight a sentence, then audio picks up from there"), which is exactly what `readerToAudio()` in `services/sync/handoff.ts` is built to do given a CFI + chapter.
- It costs ~1 day of work and removes the tail of all save-coverage edge cases.
