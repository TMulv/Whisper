## Root Cause Hypothesis

The shelf is showing exactly `40/100` because the upload phase has completed and the code is awaiting `submitJob()` — the POST to `https://api.assemblyai.com/v2/transcript`. That fetch has no timeout and no error-to-UI bridge, so any of three failure modes produces the exact symptom the user sees:

1. **Submit fetch is hanging** (most likely) — network flake, captive portal, IPv6/IPv4 issue, or the device went offline mid-call. React Native's `fetch` will wait indefinitely.
2. **Submit fetch rejected** with an HTTP error (401 invalid/expired key, 429 quota, 5xx) — the rejection is swallowed by `kickoffAssemblyAiTranscription`'s outer `.catch()` and never reaches `onStatus`.
3. **Submit fetch threw** before completing (TLS, DNS, fetch-blocked) — same swallow path.

In all three cases the shelf permanently shows `40/100` with the pulsing dot still animating. The user perceives this as "freezing"; the system thinks it's "still in progress" or "already failed and forgotten." Both states render identically.

The deeper finding: this entire failure mode is invisible because (a) `submitJob` has no timeout, (b) the only error channel is a `logger.warn` the user never sees, and (c) `TranscriptionPhase` lacks an `'error'` variant so the UI cannot represent failure.
